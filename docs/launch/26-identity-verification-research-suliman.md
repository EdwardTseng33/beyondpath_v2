## 1 · 競業身分認證機制盤點

### 1.1 對照總表

| 平台 | 發案方（client）驗證 | 接案者（worker / 專家）驗證 | 手機驗證 | 身分證 / 政府證件 | 人臉 / 照片核對 | 觸發時機 |
|---|---|---|---|---|---|---|
| **Pro360**（台灣） | 問卷 + 電話驗證（確認聯絡資訊真實）| 註冊免費、ID 或營業登記認證可拿「已認證」徽章 | ✅ 有電話驗證 | 🟡 認證徽章可選、非全部強制 | ❌ 無 | 註冊 / 認證升級 |
| **Upwork**（國際） | **付款方式驗證**（信用卡 + $1 授權 hold + 2 筆小額驗證）；7 天內未驗證則合約暫停 | 政府證件（護照 / 身分證 / 駕照）+ **自拍 / 視訊人臉比對**；7 天內完成、資料 30 天後刪 | ✅ 電話確認 | ✅ 強制（接案前）| ✅ 自拍 / 視訊（第三方比對）| 收 / 付錢前；驗證徽章另收 35 Connects |
| **Fiverr**（國際） | 較輕（主要靠付款）| 實體政府證件 + 自拍、第三方軟體驗「證件為真 + 自拍為真 + 兩者相符」| 🟡 視情況 | ✅ 強制（EU DSA 要求 2025-02 前全驗）| ✅ 自拍比對（第三方）| 對 EU 客戶接案前 |
| **104 外包**（台灣） | 企業 / 個人會員、付費才能看發案方資訊 | 付費會員才能報價、交易抽 $500-3000 | 🟡 帳號層級 | ❌ 非全部強制 | ❌ 無 | 付費會員制 |
| **BeyondPath**（現況） | ❌ 無帳號、直接填表送 | ❌ 無帳號、AI 訪談 + Edward 人工覆核 | ❌ 無 | ❌ 無 | ❌ 無 | — |

### 1.2 讀表三個重點

1. **「身分證 + 人臉」是國際大平台的標配、但只在『收 / 付錢』那一關才觸發**——不是註冊就要。Upwork / Fiverr 都是「先輕量註冊、要動錢才升級驗證」。這個分階段邏輯 BeyondPath 該抄。
2. **Upwork 的發案方驗證主力是『付款方式』不是身分證**——對 client 來說，「信用卡能扣到錢」比「身分證是真的」更能證明他不是 fake。這對 BeyondPath 有啟發：發案方的 fake 防線重點在「能不能聯絡 + 能不能付款」、不在身分證。
3. **台灣本土（Pro360 / 104）普遍比國際輕**——電話驗證 + 認證徽章為主、身分證 / 人臉非全面強制。台灣用戶對「平台要我傳身分證 + 自拍」的接受度低、會直接流失。**BeyondPath 在台灣市場、過度驗證 = 勸退轉換率。**

### 1.3 Pro360 一個要注意的資訊落差

公開資料兩個來源說法略有出入：第三方評測說「專家須過 ID 或營業登記認證才有已認證徽章」、但 Pro360 官方「如何接案」頁把照片 / 作品 / 證照寫成**加分**（選填）、不是強制門檻。我的解讀：**Pro360 的身分認證是『可選的信任加分』、不是『註冊硬門檻』**。手機 / 電話驗證才是它真正的底層 gate。這正是 BeyondPath 該採的姿態。

## 2 · 台灣合規邊界（這是我的專業守備區）

每一種驗證手段、合規負擔 vs 防 fake 強度的對照。Edward 看這張表就懂為什麼我擋身分證 / 人臉。

| 驗證手段 | 合規負擔 | 防 fake 強度 | 個資法地位 | 沙利曼判斷 |
|---|---|---|---|---|
| **Email 驗證** | 極低 | 低-中 | 一般個資、§19 同意即可 | ✅ 必做、零負擔 |
| **手機 OTP 驗證** | 低 | **中-高**（手機門號實名綁定、最划算的防 fake）| 一般個資、§19 同意即可 | ✅✅ 必做、CP 值最高 |
| **同裝置 / IP 限制** | 低（技術面）| 中（擋批量註冊）| 不蒐個資、純頻率控制 | ✅ 建議做 |
| **銀行帳戶驗證**（小額試撥 / 第三方 KYC）| 中 | 高 | 帳號非身分證、但仍敏感 | 🟡 接案者「收錢前」做、PMF 不用 |
| **身分證字號 + 影本蒐集** | **高** | 中-高 | 身分證字號 = 可直接識別個資、影本蒐集要「特定目的 + 最小蒐集 + 適當安全措施」、§27 重保管義務 | ❌ PMF 不做（負擔 >> 效益）|
| **人臉 / 照片核對（生物特徵）** | **極高** | 高 | **特種 / 生物特徵資料**——個資法 §6 + 《個人生物特徵識別資料蒐集管理及運用辦法》、需明確書面同意 + 強安全措施、蒐集門檻最高 | ❌❌ PMF 絕對不做 |
| **營業登記驗證**（B2B 發案方）| 中 | 高（對公司客戶）| 公司登記資料、公開可查 | 🟡 規模化階段、B2B 大案再上 |

### 2.1 為什麼我對「身分證」踩煞車

台灣個資法對身分證字號 + 影本蒐集的規範重點：
- 必須有**特定目的**（不能「以防萬一」就收）
- 必須**最小蒐集**（PMF 階段配對 + 聯繫、根本用不到身分證）
- 必須**適當安全維護措施**（§27——你一旦存了身分證影本、就揹上 §27 全套保管義務、外洩 = 行政罰 + 72 小時通報 + 個別通知當事人 + 信任崩盤）

白話：**收身分證 = 把一顆未爆彈鎖進你家保險箱、然後每天祈禱別被偷。** PMF 階段你的核心風險是「沒有用戶」、不是「用戶是 fake」。為了擋少數 fake 去揹身分證保管責任、本末倒置。

### 2.2 為什麼我對「人臉」踩死煞車

人臉是個資法體系裡**最高敏感度**那一檔（生物特徵、具個人唯一性、足以識別個人）。蒐集要件比身分證更嚴：
- 需明確、個別（不是公告式）的同意
- 需強安全措施
- 出事的賠償與聲譽風險最高

而且——**你自己沒有人臉比對的技術**。要做只能接第三方（FaceMe eKYC / KryptoGO / 大簽 等）、那是有金流規模、要做 KYC/AML 的平台才划算的投資。PMF 階段一個自然人配對 prototype 去蒐人臉、合規負擔、技術成本、用戶嚇跑率全部拉到頂、防 fake 邊際效益卻很低。**這是我會直接 NO-GO 的方向。**

## 3 · BeyondPath 分階段方案（PMF → 成長 → 規模化）

核心設計哲學抄 Upwork / Fiverr：**輕量註冊、要動錢才升級驗證。** 把驗證強度綁在「風險時機」上、不綁在「註冊」上。

### Tier 0 · PMF 階段（1-10 案、現在）

> 目標：擋掉明顯 fake、拿到完整聯絡資料、合規負擔趨近零、不嚇跑早期用戶。

**所有人（發案方 + 接案者）註冊：**
- ✅ Email 驗證（OAuth Google 已自帶 verified email、等於免費過這關）
- ✅ **手機 OTP 驗證**（新增——這是這階段唯一要建的硬 gate）
- ✅ 同意條款 checkbox（已有、見 doc 20）

**發案方發案前（完整資料 gate）：**
- ✅ 姓名 + **手機（必填）** + email + 身分類型（個人 / 公司）
- ✅ 資料不完整 → 不能送出發案（這就是 Edward 講的「沒有完整資料則無法發案」、直接做進 form 驗證）
- ❌ 不收身分證、不收人臉

**接案者：**
- ✅ AI 訪談 + Edward 人工覆核（已有機制）
- ✅ 手機 OTP（同上）
- ❌ 不收身分證、不收人臉、不收銀行帳戶（撇開金流期間）

**防 fake 靠：** 手機 OTP + email verified + 同裝置/IP 限制 + Edward 人工覆核（見 §5）。

---

### Tier 1 · 成長階段（接案者升級驗證、開始過錢時）

> 觸發時機：當接案者要**實際接案收錢**、或平台開始導入金流。風險升級 → 驗證升級。

**接案者接案（收錢）前：**
- ✅ 手機 OTP（已有）
- ✅ **銀行帳戶驗證**——兩條路選一：
  - (a) 小額試撥驗證（撥 NT$1 + 用戶回填金額 / 備註碼）
  - (b) 接綠界 / TapPay 等金流商的 KYC（他們已做 KYC、你借力）
  - 重點：**帳戶能收到錢 = 比身分證更實用的「真人」證明**、且金流商已揹 KYC 責任、你不用自蒐身分證
- 🟡 高 Tier 接案者（要掛高價、高曝光）：**選擇性**補強驗證（例：作品所有權聲明、過往客戶背書）、仍非強制傳身分證

**發案方（B2B）：**
- 🟡 公司客戶選填營業登記（公開可查、低負擔、增加 B2B 信任）

---

### Tier 2 · 規模化階段（嚴格、未來式）

> 觸發時機：平台有相當交易量、有詐欺案例、或要拿企業大客戶 / 對外講合規。

- ✅ 身分證 + 人臉比對——**一律接第三方 KYC**（KryptoGO / 大簽 / FaceMe eKYC / 鑑識科技）、**絕不自建、絕不自存影本**
  - 為什麼接第三方：他們揹 §6 / §27 保管責任、有活體辨識防 deepfake、有合規認證、你只拿「verified / not verified」結果不碰原始生物特徵
- ✅ 發案方企業：營業登記驗證 + 統編比對
- ✅ 此階段要另立完整 KYC / AML SOP + 律師審 + §6 生物特徵蒐集辦法合規評估（我另開 audit）

## 4 · 帳號系統建議

### 4.1 要不要建帳號？→ 要

現況「無帳號、直接填表」有三個問題：
1. 拿不到可靠的聯絡資料（Edward 點到的痛點）
2. 擋不住重複 / 批量 fake
3. 接案者 / 發案方無法回來看自己的狀態、無法累積信任資料層（這是 BeyondPath 的核心價值主張、見 doc 02 / landing「trust data layer」）

### 4.2 怎麼建？→ Supabase Auth（已有）+ 手機 OTP

你已經有 Supabase + Google OAuth（見 project-status / doc 02）。加帳號系統不用打掉重來：

**註冊流程設計：**
```
1. Google OAuth 登入（已有）→ 拿 verified email
2. 手機 OTP 驗證（新增）→ Supabase Auth 內建 phone auth、接 SMS provider（Twilio / 台灣簡訊商）
3. 填完整資料表單（姓名 + 手機 + 身分類型）→ 電話必填、寫進 profiles
4. 完成 → 才解鎖「發案 / 接案」按鈕
```

**技術重點：**
- Supabase Auth 原生支援 phone OTP（`signInWithOtp({ phone })`）、不用自建
- SMS provider：Twilio（國際、貴一點）或台灣簡訊商（每則約 NT$0.8-1.5、便宜）
- `profiles` 表加欄位：`phone`（必填、verified flag）、`phone_verified_at`、`identity_type`（individual / company）
- RLS policy 沿用 doc 02 §1 的模式（本人看本人、Edward 看全部）

### 4.3 工時估（雙軌）

| 項目 | 內容 |
|---|---|
| **任務** | 帳號系統 + 手機 OTP 驗證 + 完整資料 gate（電話必填 → 才能發案/接案）|
| **預估工時**（2026 AI 輔助工程師）| **3-5 天**（含接 SMS provider + OTP flow + profiles schema 改 + RLS + form gate + 測試）|
| **移動城堡估** | 約 **6-10 小時**（卡西法實作 + 沙利曼 Gate 5 + 馬魯克 QA + Edward 審核迭代）|
| 主要 bottleneck | SMS provider 申請 / 測試（台灣簡訊商開戶要 1-2 工作天、可並行）|

> 雙軌備註：SMS provider 開戶是外部等待、不算移動城堡淨工時。實作本體很標準、Supabase 原生支援、不是難工程。

## 5 · 防 fake 的「最小有效」組合（Edward 真正怕的那件事）

你怕的是 fake 假帳號。我給你「用最低成本擋掉約 80% fake」的組合——**不用一開始就上身分證 / 人臉。**

| 防線 | 擋什麼 fake | 成本 | 強制度 |
|---|---|---|---|
| **手機 OTP** | 擋無門號的批量機器人、一個門號一個帳號 | 極低（每則簡訊 ~NT$1）| 🔒 硬 gate |
| **Email verified**（OAuth 自帶）| 擋一次性假信箱（Google 帳號比拋棄式信箱可信）| 零 | 🔒 硬 gate |
| **同裝置 / IP 頻率限制** | 擋同一人洗一堆帳號 / 同 IP 批量註冊 | 低（Supabase Pro rate limit / 前端 fingerprint）| 🔒 軟 gate |
| **Edward 人工覆核** | 擋前三道漏掉的、靠人眼判斷異常（資料兜不攏 / 行為怪）| 你的時間 | 🔒 最後一關 |
| **完整資料 gate** | 逼 fake 付出更多偽造成本（要編一整套真實感資料才能發案）| 零 | 🔒 硬 gate |

**這套組合的邏輯：** fake 帳號最怕的是「成本」。每多一道（門號、真信箱、不同裝置、編完整資料、過人眼）、製造一個 fake 的成本就翻倍。手機 OTP 是其中 CP 值之王——綁實名門號、一支手機難洗多帳號、每則簡訊才 NT$1。**這五道疊起來、擋掉的 fake 遠超你 PMF 階段會遇到的量、而你一張身分證都沒碰。**

剩下那 20%「願意花成本繞過」的高階 fake——PMF 階段你根本遇不到（你還沒大到值得人專門攻擊）。等真的遇到、再升 Tier 1 / Tier 2、那時候你也有金流規模可以負擔第三方 KYC 了。

## 6 · 給 Edward 的一句話 verdict

**PMF 階段身分認證、做到這裡剛剛好：**

> 帳號註冊要過「手機 OTP + email 驗證」、發案前「電話必填、資料不完整不能送」、接案者照舊「AI 訪談 + 你親自覆核」。
>
> **不要碰身分證、絕對不要碰人臉。** 那是有金流規模、要對外講合規時、接第三方 KYC 才上的東西。現在上、等於替一間還沒客人的店裝三道防彈門——錢花了、責任揹了（個資法 §27 / §6 的保管炸彈）、客人還被嚇跑。
>
> 你怕的 fake、用「手機 OTP + email + 同裝置限制 + 你的人眼」這套零成本組合就擋掉八成。等你大到那 20% 高階 fake 來敲門、自然就到了該上身分證 / 人臉的 Tier 2、那時你也付得起第三方 KYC。
>
> **別過度、別裸奔——這條線剛剛好。**

下一步若你點頭：我把「Tier 0 帳號 + 手機 OTP + 完整資料 gate」開成 spec 給卡西法實作、走 Gate 1/4/5、3-5 天可上。
