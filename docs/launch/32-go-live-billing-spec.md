## 0 · 先講最重要的兩句話（讀其餘前先讀）

### 0.1 一個已存在、必須先解決的矛盾（最高優先 · 紅旗）

今天城堡已 ship 的 ECPay 金流程式（`create-ecpay-payment` + `ecpay-webhook` + `mark-commission-event` 9 步對帳）走的是：

> **客戶刷卡 → 錢進 Edward 個人綠界戶 → Edward 再撥付給接案者（代收代付 / 平台持有全額再分配）。**

但 doc 18（霍爾金流 SOP）寫死的合法路徑是：

> **路徑 D = 平台完全不持有客戶款。客戶直接付接案者，平台只跟接案者收 take rate。**

**這兩個是相反的金流結構，法律風險天差地別。** 在我簽字放行「正式收費」之前，**Edward 必先拍板用哪一個**（見 §3 + §6 必拍 1）。代收代付（現有 code 路徑）才是會碰到《銀行法》§29 / 第三方支付灰區的那個——這正是 doc 18 當初設計路徑 D 要避開的東西。**現有 code 跟既定法律策略打架，這個必須先收斂。**

### 0.2 「正式抽佣」的最低成本合法起跑路徑（PMF 階段建議）

我的務實建議，PMF 第 1-N 案（年度抽佣總額 < NT$ 8 萬／月平均營業額未達課稅起徵點前）：

> **金流走路徑 D（平台不持有客戶款）+ 平台抽佣以 Edward 個人「執行業務所得 / 服務報酬」處理 + 開立「收據」而非統一發票。**

理由：這條路 **不需要先開行號、不需要綠界商戶版、不觸發營業稅開票義務、不碰《銀行法》**，能讓 Edward 今天就合法開始收抽佣。等案量 / 月營業額成長到觸發點（§2.4）再升級行號。

**但**：現有 ECPay code 是代收代付路徑，跟這個建議不一致。所以 §5 給兩種啟用順序，看 Edward §6 必拍 1 怎麼選。

### 1.2 take rate 揭露 + 付款流程正式化（新增條款建議）

terms §3 需補一段「服務費揭露與計收方式」，明確寫給用戶看（公平交易法 + 消保法定型化契約揭露義務）：

> **平台服務費揭露**

> - 一次性案：依接案者 Tier 收 17-20%；retainer 月繳：依 Tier 收 20-23%（明細見 §3.2 表）。
> - 服務費於〔金流路徑決定的時點〕計收，平台同步開立〔收據 / 電子發票〕。
> - 客戶端不另收平台費；客戶支付之案款全額屬接案者本業收入（接案者自行對客戶開立憑證 + 報稅）。
> - 費率調整適用 §4.3 之 30 日預告期。

### 1.3 ⚠️ Tier 階梯一致性問題（必修 · 給卡西法 + 蘇菲）

**現況不一致**：
- `commission-calc.ts` 的費率表 = **依 Worker Tier**（B20/B+19/A18/A+17/S17%，retainer 各 +3%）
- terms.html §3.2 的費率表 = **依案件 ACV 金額**（0-5萬 20% / 5-20萬 18% / 20萬+ 17%）

這兩個是**不同的計費維度**（Tier vs 金額），條款寫的跟程式算的不一樣 = 用戶看到的費率 ≠ 系統收的費率 = 定型化契約揭露不實風險 + 出帳爭議。

> 沙利曼 verdict：條款必須跟程式 SSOT，否則第一筆抽佣帳單就會被接案者質疑「條款寫的是 20%（依金額），你怎麼收我 23%（Tier B retainer）」。這是 NO-GO 級不一致，啟用前必修。

## 2 · 發票合法性（Edward 個人沒公司 · 關鍵決策）

平台（Edward 個人）收抽佣後、如何合法開憑證 + 報稅。三個選項，由低成本到高成本。

### 2.1 三選項對照表

| 維度 | A · 個人執行業務所得 | B · 商業登記（行號 / 獨資） | C · 有限公司 |
|---|---|---|---|
| **法律性質** | 個人提供勞務/服務的報酬 | 營業人（小規模 or 一般） | 法人 |
| **能開什麼憑證** | **收據**（非統一發票）；接案者付服務費，Edward 開收據 | 小規模：免用統一發票，國稅局**代徵 1% 營業稅**、開收據；一般：開**統一發票**、5% 營業稅 | 開**統一發票**、5% 營業稅 |
| **報稅方式** | 併入個人綜所稅，列「執行業務所得」（成本費用率扣除或核實認列） | 小規模：查定課徵（國稅局按營業額核定）；一般：每 2 月申報營業稅 + 年度營所稅 | 營所稅 20% + 營業稅 5% + 負責人薪資所得 |
| **設立成本** | **NT$ 0**（不需登記） | NT$ 1-3K 規費 + 可能刻章 + 記帳（DIY or 月 NT$ 2-4K） | NT$ 5-15K 設立 + 資本額 + 記帳月 NT$ 3-6K + 可能簽證 |
| **報稅負擔** | 低（一年一次併綜所稅） | 中（小規模查定低；一般需雙月申報） | 高（需會計師 / 記帳士、雙月+年度） |
| **適用案量** | **PMF 第 1-N 案**；年抽佣總額低、案量少 | 月營業額 > NT$ 8 萬（達營業稅起徵點）或客戶要統編發票 | 接企業客戶、需公司主體簽約、月流水 6 位數+ |
| **客戶端觀感** | 收據可抵帳但企業客戶可能要統一發票 | 小規模收據 / 一般統一發票，企業可接受 | 最正式，企業採購最無阻力 |
| **碰《銀行法》風險** | 與金流路徑有關（見 §3），與此選項無關 | 同左 | 同左 |

### 2.2 關鍵法律要點（人話）

- **「個人收抽佣要不要開發票」的核心**：在台灣，**只有「營業人」才開統一發票**。Edward 個人沒做商業登記 = 不是營業人 = **不能也不需要開統一發票**，開「收據」即可。這是選項 A 能成立的基礎。
- **營業稅起徵點**：個人若「以營利為目的、持續性銷售勞務」，**月銷售額（營業額）達 NT$ 4 萬（銷售勞務）就應辦營業登記**。⚠️ 這是選項 A 的天花板——抽佣是「持續性提供媒合服務」，一旦月抽佣收入穩定超過 NT$ 4 萬，國稅局可認定應辦登記。（銷售貨物起徵點 NT$ 8 萬、銷售勞務 NT$ 4 萬，**抽佣屬勞務**，用 4 萬這條較嚴的線。）
- **執行業務所得 vs 薪資/其他所得**：媒合服務費較接近「執行業務所得」或「其他所得」，併入綜所稅。金額小時，國稅局通常不會主動要求登記，但**達起徵點後就有登記義務**，不是「想不想」的問題。

> **這裡我必須誠實**：個人「持續性收抽佣」在稅法上的精確定性（執行業務所得 vs 應辦營業登記）是有模糊地帶的，金額小時實務上寬鬆，但**達 NT$ 4 萬/月銷售勞務起徵點就應辦登記**。第一筆較大金額前，或月抽佣接近 4 萬時，**建議找記帳士確認一次**（諮詢費約 NT$ 1-2K，比事後補稅+罰鍰便宜太多）。這是底線建議、非正式稅務意見。

### 2.3 沙利曼建議（PMF 階段）

> **PMF 第 1-N 案用選項 A（個人執行業務所得 + 開收據）。**
> - 零設立成本、今天就能合法開始收抽佣
> - 開「服務費收據」給接案者（不是統一發票），接案者拿收據列自己的成本費用
> - Edward 年度併綜所稅申報「執行業務所得 / 其他所得」
> - **配套**：每筆抽佣留存收據副本 + 對帳紀錄（`commission_records` 已有），作為報稅憑證

### 2.4 何時必須升級（明確觸發點）

| 觸發信號 | 升級到 | 為什麼 |
|---|---|---|
| 月抽佣收入接近 / 達 **NT$ 4 萬（銷售勞務起徵點）** | 行號（小規模營業人） | 達起徵點有營業登記義務、不辦會被補稅 + 罰鍰 |
| 客戶 / 接案者**要求統一發票**（企業要報帳） | 行號（一般營業人）或公司 | 個人收據企業可能不收 |
| 開始接**企業客戶**、對方要跟「公司」簽約 | 有限公司 | 法人主體簽約 + 採購流程 |
| 月流水穩定 **6 位數**、或要募資 / 找投資 | 有限公司 | 主體正式化、會計帳完整 |
| 要做**真實 escrow / 代收代付規模化** | 公司 + 評估第三方支付特許 | 見 §3 金融法邊界 |

## 3 · 金流法規邊界（代收代付 vs 路徑 D · 核心紅線）

### 3.1 兩種金流結構的法律差異（決定一切）

| 維度 | 路徑 D（doc 18 既定 · 平台不持有客戶款） | 代收代付（現有 ECPay code 路徑 · 平台持有全額） |
|---|---|---|
| 錢的流向 | 客戶 → 接案者帳戶（直付）；接案者再付 take rate 給平台 | 客戶 → **Edward 個人綠界戶** → Edward 撥付接案者 + 扣抵 take rate |
| 平台是否持有客戶款 | ❌ 不持有 | ✅ **短暫持有全額** |
| 《銀行法》§29 風險 | **無**（平台只收自己的服務費 = B2B 服務交易） | **有灰區**：持有他人款項再轉付，可能被認定「辦理匯兌 / 準收受款項」 |
| 《電子支付機構管理條例》 | 不適用 | **可能適用**：代理收付實質交易款項達一定規模需特許（資本額門檻極高） |
| 起跑合法性 | ✅ Y1-Y2 完全合法、無需執照 | ⚠️ 小規模 + 短期 + 即時撥付實務上灰，但**不是乾淨的合法** |
| 對帳複雜度 | 低（平台只記自己收的 take rate） | 高（9 步對帳：client_paid → worker_paid_out → commission_collected） |

### 3.2 我之前擋過「全額持有」的理由，現在依然成立

doc 18 §3 寫得很清楚：《銀行法》§29「非銀行不得經營...辦理國內外匯兌業務」。**平台代收代付（持有客戶全額再分配）= 正是這條的灰區。** 一旦規模化或被檢舉，認定為「代理收付實質交易款項」就會落入《電子支付機構管理條例》，那需要特許執照（資本額 NT$ 5 億級），BeyondPath Y1-Y2 完全達不到。

**所以現有 ECPay code 雖然技術上 ship 了、Edward 鑰匙也設好了，但它跑的是法律上較危險的那條路。** 這不是「能不能跑」的問題，是「該不該用這個結構正式收費」的問題。

### 3.3 個人戶 NT$20 萬/月上限 + 何時升綠界商戶版

- 現有 code 已硬編 `amount_ntd <= 200000` 提示（create-ecpay-payment L177），對應個人戶月收款上限。
- **個人戶月收款上限 NT$ 20 萬**是綠界對「個人賣家」的限制；超過需升「商戶版」，**商戶版需公司 / 行號登記**。
- ⚠️ 但這個 20 萬上限**只在代收代付路徑才是問題**——因為代收代付下「客戶全額」都流經 Edward 綠界戶（單筆 5 萬案 × 4 筆就頂到上限）。**路徑 D 下平台只收 take rate（每案幾千到萬把），月上限根本碰不到。**

### 3.4 沙利曼的金流 verdict（強烈建議）

> **PMF 階段走路徑 D，不要用現有的代收代付 ECPay code 正式收費。**
>
> 理由：
> 1. 路徑 D 乾淨合法（doc 18 既定策略、不碰《銀行法》）
> 2. 路徑 D 下個人戶 NT$20 萬月上限碰不到（平台只收 take rate）
> 3. 路徑 D 下選項 A（個人收據）成立，零設立成本起跑
> 4. 代收代付的 9 步對帳複雜、且把 Edward 個人戶曝險在《銀行法》灰區
>
> **現有 ECPay code 不浪費**：保留作為「客戶刷卡付接案者」的**支付通道**（綠界支援收款方設定），或留待 Y3+ 月流水 ≥ NT$500 萬評估真實 escrow 時再用代收代付 + 特許評估。但**正式收費的計費 + 開憑證走路徑 D**。

### 3.5 何時必須改結構（案量/金額觸發點）

| 觸發 | 動作 |
|---|---|
| 月流水（經手案款）≥ NT$ 500 萬 + 累積爭議 ≥ 5 | 評估真實 escrow / 第三方支付合作專戶（doc 18 §7 已定） |
| 客戶強烈要求「平台託管 / 履約保證」 | 評估與綠界/藍新「實質交易款項代收付」合作（需公司 + 可能特許） |
| 跨境案款開始有量 | 另案評估外匯 + 跨境支付合規（terms §1.3 已預留 Y2-Y3） |

## 4 · 退費機制可執行性（terms §5 → 真的能退）

Edward 選 B = terms §5 退費 5 情境從「預告」變「現行生效」。我確認「真的能退」。

### 4.1 退費可執行性 × 金流路徑

| 退費情境 | 路徑 D 下怎麼退（建議路徑） | 代收代付下怎麼退 |
|---|---|---|
| A · 配對前撤案（100%） | 客戶根本還沒付接案者 → 無金流發生、平台無收 take rate → **無退費動作**（最乾淨） | 平台從代收款全額退客戶（綠界退刷 / 個人戶匯回） |
| B · Worker 全婉拒（100%） | 同 A，客戶未付 → 無退費 | 同 A |
| C · 平台技術故障（100%） | 若已收 take rate → 平台退 take rate；案款是客戶付接案者、平台不經手 | 平台退全額 |
| D · Worker 接受後未交付（抽佣 50% 退） | 平台退「已收 take rate 的 50%」給客戶/接案者（依條款）；案款追討走接案者 | 同 |
| E · 期待落差（原則不退） | 無金流動作 | 無 |

> **路徑 D 的退費優勢**：絕大多數退費情境（A/B）根本沒發生金流，平台無需「退錢」——因為平台從沒持有客戶款。**這正是路徑 D 比代收代付乾淨的又一證據。**真正要退的只有「平台已收的 take rate」，金額小、可控。

### 4.2 綠界退刷 / 個人戶退款可執行性確認

- **綠界信用卡退刷**：綠界 AIO 支援退款 API（部分退 / 全退），需在原授權有效期內（通常 180 天）。代收代付路徑才會用到。
- **ATM / 個人戶退款**：Edward 個人手動匯回客戶帳戶，留轉帳紀錄。
- **路徑 D 下**：客戶款本就在接案者手上，平台只退自己收的 take rate（手動匯回，金額小）。
- ⚠️ **退費條款生效 = 消保法網購 7 日鑑賞期適用性需評估**：媒合服務是否屬「通訊交易解除權」適用範圍有解釋空間（服務一經提供配對即難回復原狀，可能落入排除事由）。terms §5 已設「配對前 100% 退」實質已涵蓋鑑賞期精神，但**正式收費前建議在 terms 補一句「本服務性質為媒合，配對完成後依消保法施行細則屬不適用 7 日解除權之服務」並由律師確認措辭**。

### 4.3 退費 SOP 落地（給 Edward + 卡西法）

- 退費請求入口已有（terms §5 共通條件：email 申請）。
- 需在 admin.html 加「退費處理」記錄欄（呼應 mark-commission-event 可加 `event_type='refund_issued'`，目前 VALID_EVENTS 只有 4 種，需擴充）。
- 退費時限（7/14/30 工作天）已在條款，Edward 需有 SOP 確保 SLA 不破（出事時這是合規證據）。
