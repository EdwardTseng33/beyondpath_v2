### 2.2 欄位說明

**ID 預留**：保留 C01-C10 編號、方便 file #16 BD 劇本檔追蹤、Edward 不用改

**真實姓名**：對方名字（可以只寫「Joe」「Mei」這種 first name、足夠霍爾個人化）

**公司/工作室**：對方公司名 / 工作室名（若 freelancer 寫「個人 / freelance」）

**email / 聯絡方式**：
- 老朋友寫「LINE / iMessage」即可
- 商務對象寫 email
- LinkedIn DM 對象寫 LinkedIn URL 或「LinkedIn DM」

**你的關係（多久、深淺）**：霍爾依此選 outreach 訊息語氣
- 例 1：「認識 5 年 / 一起做過 1 案 / 信任 8/10」→ 用 file #23 套 1 LINE 老朋友直接版
- 例 2：「LinkedIn 既有 follower / 互動過 1-2 次 / 信任 4/10」→ 用 file #23 套 3 LinkedIn DM 冷推版
- 例 3：「朋友轉介 / 沒直接認識 / 信任 3/10」→ 用 file #23 套 2 Email 商務版

**vertical**：簡單分類、決定 retainer 適合性 + 試做案類型
- DTC = 電商品牌主
- SaaS = B2B 軟體
- 設計 = 設計工作室 / 個人設計師
- 內容 = 內容創作者 / 工作室
- 顧問 = 顧問公司 / 個人顧問
- 其他 = 寫具體（EdTech / FinTech / 餐飲 / 健身 / etc）

**預估 ACV**：
- 一次性 = 試做案預估報價區間 NT$ X 萬
- 月 retainer = 若升級月繳的預估月費 NT$ Y 萬
- 例：「8-15萬 / 3萬月」

**retainer 適合性**（霍爾 5/28 判定 3 vertical 高適合）：
- **高**：DTC AI 自動化 / B2B SaaS GTM 助理 / 內容創作工具鏈（持續需要 AI 交付）
- **中**：設計工作室 / 顧問公司（不定期但需要）
- **低**：一次性專案多、不需持續維運的（例如品牌設計案、活動策劃）

**推薦優先序**：
- **W1**（6/3-6/10）：最深關係、最有把握的 2-3 個
- **W2**（6/10-6/17）：次深關係 / 已有對話脈絡的 2-3 個
- **W3+**（6/17 起）：較淡關係 / LinkedIn 冷推類 2-4 個

**備註**：任何霍爾應該知道的個人化線索
- 對方公司近況（剛融資 / 擴張 / 痛點）
- 對方對 AI 的態度（早期採用 / 觀望 / 抗拒）
- 上次見面聊了什麼（霍爾可在訊息開頭呼應）
- 要避開的話題 / 對方敏感點
