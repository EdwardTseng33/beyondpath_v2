## 0. TL;DR · 這份 deck 解什麼問題

**Client 拿到一次性 case 結案後、Edward / 霍爾 pitch retainer 月繳**：
- 客戶 80% 反應「為什麼要月繳？我下次需要再找你就好」
- 一頁 PDF 是 visual aid、3 分鐘 pitch 對話的 anchor
- **不是 sales sheet**、是「**為什麼 retainer 比一次性對你更有利**」的證據

**核心 thesis**：retainer 不是平台收更多錢、是「**讓客戶的 AI 工作流不歸零**」。一次性結案 = 知識散落、人重來。Retainer = 同一個 worker + 同一套工作流 + 持續優化。

### 1.2 為什麼 retainer 不是一次性 · 4 個 value prop（佔 2/6 頁高 · 第二段）

**標題**：為什麼月繳比每次找新人划算

四個 value prop 用 2x2 grid 或 4 列 layout：

#### Value Prop 1 · 算力持續預留
> 月繳 = 你的 AI 算力配額 buffer 提前 lock 住、不用每次案子重新排檔期
> 一次性 = 旺季可能等 2-4 週才能配對到 worker

#### Value Prop 2 · 持續優化、不歸零
> 同一個 worker 累積你公司的 prompt 偏好、品牌 voice、業務 context、6 個月後比月初快 3 倍
> 一次性 = 每次都從零開始解釋你公司是做什麼的

#### Value Prop 3 · 維運包含（不另收費）
> Bug 修復 / prompt 微調 / 模型升級 / 工作流改版 全月內無限次、不另計費
> 一次性 = 結案後任何修改都要重簽 small case

#### Value Prop 4 · 變動需求彈性
> 月需求 ±30% 內彈性吸收（這個月 80h / 下個月 110h 不調整月費）
> 一次性 = 每改 scope 都要重議價

**設計提示**（給女巫）：
- 4 個 prop 用 icon + 1 句標題 + 2-3 行說明
- icon 視覺 = 簡潔線條風、不用 stock photo
- 對比格式可以用「✓ Retainer ··· vs ⌀ 一次性 ···」雙列

---

### 1.3 NT$ 3 萬透明拆解（佔 1.5/6 頁高 · 第三段）

**標題**：你的 NT$ 3 萬月費花在哪 · 透明拆解

| 項目 | 金額 | 說明 |
|---|---|---|
| 接案者月度服務 | NT$ 15,000-18,000 | 你的 dedicated worker 月度交付時間（核心 60%） |
| AI 系統使用費 | NT$ 4,000-6,000 | LLM API（Claude / GPT-4 / etc）+ 工具訂閱（v0.dev / Cursor / Figma / etc） |
| 平台抽成 | NT$ 5,000-7,000 | BeyondPath 配對 + 維運 + 客服 + 法務（17-23%） |
| 維運 buffer | NT$ 1,500-2,000 | 月度 bug fix + 變更 SLA 內無限次 |
| Markup | NT$ 1,000-2,000 | 平台正常 markup（不藏帳） |

**為何這樣寫**：
- **透明 = 信任**：客戶最怕「平台收 30K 我不知道實際 worker 拿多少」、直接 break down 解這懷疑
- **接案者占 50-60%**：證明平台不剝削 worker、給 worker 公平比例
- **平台抽 17-23%**：對比 Upwork 20% 抽成、BeyondPath 沒過頭
- **markup 1-2K**：誠實認「我們有 markup」、不假裝平台不賺錢

**設計提示**（給女巫）：
- 表格 visual 用 horizontal bar chart 也可、視覺化 50-60% / 13-20% / 17-23% / 3-7% / 3-7%
- 別用圓餅圖（太多區塊難讀）
- 顏色 coding 用品牌色階（worker 給最深、平台抽成淺一點）

### 1.4 月度節奏範本（佔 1/6 頁高 · 第四段）

**標題**：你的 Retainer 月度節奏

```
W1                   W2                   W3                   W4
──────────────────────────────────────────────────────────────
Brief                Deliver              Review               Next Brief
↓                    ↓                    ↓                    ↓
你 + worker          worker 交付          一起 review          下個月需求
30 分鐘對齊          月度 deliverable     什麼改進、什麼保留   開始 brief
這個月要什麼
```

**4 個節奏 phase**：
- **W1 Brief**：30 分鐘對齊會、你說這月需求、worker 提案 approach
- **W2 Deliver**：worker 交付主 deliverable（依產業可能是文案 / 圖像 / 自動化 / 程式碼）
- **W3 Review**：一起 review、什麼改進、什麼保留進下個月
- **W4 Next Brief**：下個月需求開始 brief、循環

**為何這樣寫**：
- 客戶最怕「月繳但不知道每個月怎麼運作」、節奏給確定感
- W3 Review 明確列出 = 客戶有 voice、不是被動接受
- W4 → W1 循環 = 視覺化「持續」、不是斷裂的月度

**設計提示**（給女巫）：
- horizontal 4-column timeline、用箭頭或線條連接
- 每 column 用 icon + 標題 + 1 行說明
- W4 → W1 用 loop 符號或 cycle 視覺、強調循環

### 1.5 SLA 5 條（佔 1/6 頁高 · 第五段）

**標題**：服務承諾 · SLA

| # | 承諾 | 數值 |
|---|---|---|
| 1 | Response time | 24 小時內回覆 |
| 2 | Uptime | 99.5% 平台可用 |
| 3 | 月度 deliverable | 80-110 小時彈性、含 ≥ 1 主 deliverable |
| 4 | Bug fix | 結案後 30 日內 bug 免費修 |
| 5 | AI 用量上限 | 月度 LLM API tokens ≤ 約 NT$ 5,000 等值（超量再協商） |

**為何這樣寫**：
- 客戶買 retainer 最怕「我月繳但你沒交付」、SLA 是反向保障
- 每條 SLA 對應一個典型擔憂、解決客戶心中問號
- 第 5 條 AI 用量上限 = 誠實「token 不是無限」、避免後期糾紛

**設計提示**（給女巫）：
- 5 條 SLA 用 checkmark + 1 句 + 數值的緊湊 layout
- 強調「24 小時」「99.5%」「30 日」這些具體數字
- 不要用很長的法律條款語氣、要像承諾書

### 1.6 適合 retainer 的 3 vertical · 案例敘事（佔 0.5/6 頁高 · 第六段）

**標題**：誰最適合 Retainer · 3 個 vertical

#### Vertical 1 · DTC AI 自動化
> 「電商品牌主每月需要新文案 + 圖像 + 客服自動化更新、Retainer 配對的 worker 變成你的延伸 team。」
> 典型客戶：月營收 NT$ 100-500 萬 DTC 品牌

#### Vertical 2 · B2B SaaS GTM 助理
> 「SaaS 創辦人需要持續 outbound / content / case study / demo，Retainer worker 變成你的兼職 GTM。」
> 典型客戶：年營收 NT$ 1000-5000 萬 SaaS 公司

#### Vertical 3 · 內容創作者 AI 工具鏈
> 「Solo creator 或小工作室需要持續 AI 影音 + 自動剪輯 + 縮圖 + SEO 字幕，Retainer worker 變成你的 production 助理。」
> 典型客戶：YT/Podcast 訂閱 1萬+ 創作者

**為何選這 3 vertical**：
- 都有「**持續、可預測、月度節奏**」的 AI 需求
- 都不適合「找一次性 worker 又找下一個」的斷裂模式
- 都有「**knowledge accumulation 帶來 ROI**」的特性（worker 越熟你公司、產出越好）

**設計提示**（給女巫）：
- 3 個 vertical 用 3 column 並排
- 每 column 用 icon + 標題 + 1 句敘事 + 1 行典型客戶
- 不用 case study 圖（W1-W6 還沒實際案例）、敘事即可
