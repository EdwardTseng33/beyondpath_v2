**整個 `docs/` 內部文件目錄 + `STATUS.md` 被當靜態檔部署到正式站、公開可讀。**

實測（從正式站直接抓、無需登入）：
- `https://beyondpath.tw/docs/launch/00-launch-plan-sophie.md` → 回傳完整內容（含上線策略、Edward 個人行動清單、NO-GO 條件）
- `https://beyondpath.tw/docs/launch/02-trust-audit-suliman.md` → 回傳完整資安稽核文件，**公開暴露**：
  - Supabase project ID `iacwmkcloxjffghrweie`
  - admin email `edwardt0303@gmail.com`
  - 一整份「目前還有哪些未修安全弱點」清單（RLS disabled、localStorage token、open redirect…）= 等於把攻擊地圖送給攻擊者
- `https://beyondpath.tw/STATUS.md` → 回傳完整內部狀態

**為什麼嚴重**：
1. 商業策略、費率邏輯、競品分析、單位經濟全公開給競爭對手（`docs/launch/` 40+ 份）
2. 資安稽核文件公開 = 把「我們哪裡還沒守好」主動告訴攻擊者
3. publishable key 本身設計成可公開（anon key，這條不嚴重），但「弱點清單 + 系統 ID 同時公開」放大了其他每一條風險

**根因**：`prototype-v0.2/` 沒有 `.vercelignore`，`vercel.json` 也沒擋 `docs/` 與 `*.md`，Vercel 把整個目錄當靜態站全部上線。

**修法（低風險、可逆）**：加 `.vercelignore` 排除 `docs/`、`*.md`、`design-source*/`、`archive/`、`prototype/`（v0.1 備份）；或在 `vercel.json` 加路由把 `/docs/(.*)` 與 `/*.md` 回 404。改完重新部署即生效。屬部署層動作，建議交卡西法/沙利曼執行 + Edward 點頭。

## 3 · 跨層共通主題（整合層真正的價值 · 合成用戶痛點 ←→ 專業 audit 程式證據雙向印證）

下面 8 個主題，每一條都是「至少一位合成用戶踩到 + 至少一位專業 agent 在 code 裡找到對應證據」，互相印證、不是單方猜測。

### 主題 A · 金流訊息全站精神分裂（最大系統性問題 · 跨 4 個來源）
模式A（平台不碰錢）→ 模式B（綠界代收代付）切換沒清乾淨，同一個產品對用戶同時承諾兩種互斥金流：
- **C1 阿宏**（合成用戶）：估價卡寫 `+15% platform premium`，但條款說「客戶端不另收平台費」→ 直接懷疑隱藏費用，列為 blocker
- **霍爾 P0**：`steps-5-8.jsx` Step7 整面「付款由雙方自行處理/平台不保管專案款」舊文案、prod 在跑、還沒走 i18n
- **沙利曼 P1**：landing dict + 寄給 client 的 email 共 6 處仍寫「雙方直接結算（BeyondPath 不碰錢）」，與同頁代收代付互斥 → 金流爭議時會被用戶反咬
- **霍爾 P1**：英文版用 `escrow/payment custody`，條款卻明寫「非 escrow」→ 中英文兩種法律人格
> 這是上線前最該優先收的一條：不是改一個字，是 6+ 處寫死文案 + 中英 dict + email 模板全面對齊代收代付。

### 主題 B · 預算門檻把小案直接擋在門外
- **C3 雅婷**（5 萬試水）：Step02 預算滑桿最低 NT$100K，她的 5 萬落在門檻外、無說明無替代路徑 → blocker，當場關頁
- 與首頁 staticbar 標榜「FIRST PROJECT NT$50K+」、條款保底 5 萬自相矛盾

### 主題 C · worker 全匿名 sample、技術買家無法驗真
- **C2 Kevin**（SaaS CTO 找 RAG 工程師）：worker 全匿名 `@agent.rag.01`、無 GitHub/portfolio/技術 badge、只有 NPS → 「叫我怎麼信他能寫 eval pipeline」，轉去 Upwork
- **C1 阿宏**：分不清 worker 是真的還是 demo sample
- 對照 Upwork 可看真名 + GitHub + 技術測試 = 直接的轉換殺手

### 主題 D · 費率藏在條款裡、worker 第一個要找的數字找不到
- **W1 Iris**（資深顧問）：landing Tier 區塊講了半天能賺多少，就是不講抽幾趴，要跳去翻 legal 才知道 → 進警戒模式不是申請衝動
- **W4 老張**（15 年老手）：同樣第一個找費率
- 女巫也標 landing Tier 區塊零費率數字

### 主題 E · 領域不在池子 = 投入後才被拒（bait-and-switch 體驗）
- **W3 Mia**（Midjourney 接案）：走完 intro 才在 generate 步驟發現只收三個主場領域、她的領域要「先加 waitlist」、不知等到何時
- **W5 Vivian**（加拿大台裔）：花 30-45 分鐘走完 AI 訪談、最後一步才被告知「Y1 僅限台灣、國際版上線後開放」
- **C2 Kevin**：RAG 子領域 worker pool < 3 人觸發 disabled 灰態
> 共同根：把「你不能用」這件事放在用戶投入大量時間之後才講。

### 主題 F · 英文版法務缺失擋死外籍企業客
- **C5 Daniel**（外商 ops director、NT$200K 案）：terms 全中文、無英文版，checkbox 的英文 i18n key 缺、錯誤提示也 fallback 成中文 → 無法代表公司同意看不懂的條款，硬性 hard stop

### 主題 G · 沒有回購鉤子 + 不記得回頭客（北極星量不出來）
- **C6 明哲**（回購測試）：回來像第一次、身分要重選、條款要重勾、找不到上次的案子 → 「記得你是誰應該是最基本的吧」
- **蕪菁頭 P0×3**：埋點只存本機 admin 看不到、worker 端零埋點、client 回購計算程式根本不存在
- **蕪菁頭 P1**：掃過所有 Edge Function，沒有任何「結案後 N 天提醒回來發第二案」的機制
> 北極星=雙邊 60 天回購率，但目前產品內沒有任何讓用戶回來的設計，也沒有能力量到它。

### 主題 H · 違約金/個人營業者信任衝擊出現得太早太突兀
- **C1 阿宏**：還沒看到配對結果、Step01 checkbox 旁就標「含 §8 違約金倍率」→ 「我還沒簽約你就跟我說違約金？」；再查到「Edward Tsai 個人營業者」→「幾十萬交給一個人在跑的平台，不敢」

## 6.5 · 主對話補驗 · 女巫手機版缺口（誠實留痕）

女巫在視覺面向誠實標了一條驗收缺口：發案/接案兩頁的手機版她沒拿到真截圖（preview 工具中途停了）。整合時這條本來被我吞掉沒上報，Stop hook 抓到、我自己起本機畫面用座標量測補驗（截圖工具同樣卡住，改量每個區塊實際座標，比模糊截圖更硬）：

| 頁面 | 手機版（375 寬）結果 |
|---|---|
| **發案頁** app.html?role=client | ✅ 乾淨——零元素超出螢幕、無橫向捲軸、無裁切 |
| **接案者後台** app.html?role=worker | ⚠️ 右側「我的數據 / 下個里程碑」整欄被推出螢幕右邊、切在畫面外（worker 在手機上看不到自己的 NPS、完成案數、NEXT MILESTONE 卡片）。`.bp-rail` 寬 360px 在 375 視窗沒堆疊到主內容下方。所幸沒造成整頁橫向捲軸（被 overflow 切掉而非撐破版面） |

→ 證實卡西法 P2 + 女巫 P2「手機版 app 右欄未堆疊」屬實、且影響可感（接案者手機上看不到自己的成績）。修法同原 P2：加窄螢幕斷點讓右欄堆疊到下方。發案頁手機版過關、不需動。

## 7 · 一個要 Edward 拍板的策略級事項（霍爾標出 · 非 bug）
沙利曼 5/29 的 32 號計畫書把「代收代付」標為《銀行法》§29 灰區、建議走路徑 D；Edward 拍板逆向走代收代付。**這是「明知灰區仍走」的決定、不是疏漏。** 商業上可接受（撐得起責任上限承諾 + 降低繞過平台 + client 信任感強），但前提是清楚三件事：(a) 個人戶代收代付的曝險、(b) 月經手案款逼近門檻時的主體升級路徑、(c) 對外絕不能聲明「平台不持有金流」（那是路徑 D 招牌、代收代付用會變不實陳述——正好對上主題 A 要清的舊文案）。
